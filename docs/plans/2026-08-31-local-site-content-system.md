# 本地高保真站点内容与页面系统

## 目标

本轮只在本地 Hydrogen 工作区完善站点，不提交 GitHub、不部署 Oxygen、不写入 Shopify 页面内容。目标是让所有公开入口先具备可阅读的首屏、明确的下一步、统一的视觉容器，以及在真实数据为空时仍然可用的空状态。

## 视觉方向

- 定位：传统工艺 × 编辑部式精品电商。
- 画面：米白纸张底、墨黑结构、旧金色编号、朱印红只用于品牌印记。
- 版式：统一 `--content-max` 与 `--content-gutter`，全屏色块只用于首屏和重点 CTA；正文、目录、购物车、文章全部回到同一内容宽度。
- 字体：系统中文正文搭配 Georgia 斜体英文/数字，避免过度装饰，保证中文可读性与移动端稳定性。
- 素材：本地缓存参考站点公开页面中的工作室、证书与节目画面，作为高保真原型素材；每张图提供用途与 alt 文本，之后可替换成店主授权原图。

## 内容模型

所有页面内容按四种类型组织：

1. **事实**：历史、人物、资质、媒体；需要来源或核验状态。
2. **解释**：工艺、材料、规格、保养；帮助用户理解，不代替商品页。
3. **业务**：库存、价格、交期、配送、退款；以 Shopify 和最终咨询为准。
4. **行动**：浏览、加入购物车、联系、阅读；每个模块至少一个明确下一步。

公开内容继续使用“六代传承”作为品牌概述，但当前人物公开到已经参与传承与当代经营的几代人，不公开第六代个人资料。

## 兼容性与可用性验收

- 桌面：内容最大宽度统一，目录与文章不再出现页面级宽度漂移。
- 平板：两栏自动收窄为可读的单列/双列，图片不撑破容器。
- 手机：菜单、下拉、折叠问答、浮动咨询按钮可点击；正文行长、按钮触控区域和图片比例稳定。
- 键盘：所有链接、按钮、`details/summary`、菜单入口都有可见 focus 状态。
- 数据：商品、分类、文章、图片、评论分别处理 loading、空值和错误，不因缺少一张图而隐藏整页。
- 结账：加购仍走 Shopify Cart，结账仍由 Shopify Checkout 处理；本轮不改变支付逻辑。

## 本地验收顺序

1. 首页、目录、分类、大师订制、品牌、工艺、指南、博客逐页打开。
2. 检查页面宽度、繁体中文、图片 alt、链接目标和移动端折行。
3. 检查商品详情幻灯片/规格/评论空状态、购物车和结账入口。
4. 运行 `npm run lint` 与 `npm run build`。
5. 只保留本地改动，等待店主回来统一检查后再决定是否通过 GitHub Desktop 推送。
